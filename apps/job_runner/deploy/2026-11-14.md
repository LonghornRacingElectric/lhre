# Initial live deployment — 2026-11-14

The dashboard runs under telemetry's existing `electric` PM2 daemon as
`lhr-jobs`. The HIL worker runs under systemd as `lhr-runner`, with a separate
`lhr-job-ssh` account and forced-command key. Base source is merged commit
`cde7e404`, plus the PM2 native-launch, FMU scratch and SQLite ownership fixes in this
change.

## Access and persistence

The HTTP listener is `127.0.0.1:8091` on telemetry. An operator SSH tunnel
provides local browser access. No domain, new Tailscale Serve listener or
Funnel setting was added. The previous public route is unchanged.

The configuration and dedicated worker key live under
`/home/electric/.config/lhr-jobs`, outside the checkout. Bootstrap credentials
are stored there in a mode-0600 operator file; no credentials appear in this
record. The HIL host key was obtained over the existing verified SSH session
and installed in the dashboard's dedicated known_hosts file.

The worker is enabled at boot. PM2's saved process list includes both
`viewer_tool` and `lhr-jobs`. Telemetry still has its existing PM2 startup
behavior: no new system-level PM2 startup unit was installed. Saved process
configuration alone does not guarantee dashboard startup after a host reboot.

## Acceptance

| Check | Observed result |
| --- | --- |
| Authenticated UI and health | HTTP 200 through telemetry loopback and the local SSH tunnel |
| Restricted SSH bridge | Status RPC succeeds with the dedicated key and strict host verification |
| CPU smoke | Five-second job succeeds; archive contains final metadata, JSON summary and both logs |
| Queued cancellation | Job becomes cancelled without starting a container |
| Running cancellation | Container stops and job becomes cancelled |
| Pause/resume | Queued starts pause; persisted pause survives both service restarts; queue left resumed |
| Restart recovery | A running 90-second CPU job keeps its container ID through worker restart and succeeds after dashboard restart |
| FMU timing | One profile completes all 12 simulated seconds in 80.563 wall seconds; weighted step mean 132.508 ms |
| GPU check | Existing NVIDIA rendering-check image exits successfully; logs downloadable |
| Existing telemetry | All 11 original container IDs/states, viewer process and public route unchanged |
| Database lifetime | 4,000 database operations leave descriptor count at 4; the running worker stays at 4–6 descriptors over 30 seconds |
| Permissions | Runner has Docker membership; SSH account does not; code/bridge/sudoers root-owned; state mode 0700 |

The first FMU attempt failed because Docker mounted scratch with `noexec`.
After applying the template-specific executable tmpfs fix, the full FMU profile
and an independent native-library load probe pass. The failed preflight remains
in history rather than being erased. Solver diagnostics remain in the logs;
this validates standalone job execution, not full autonomy/Gazebo accuracy.

The first PM2 launch imported the server without starting its HTTP listener.
The native Node/fork configuration fixes this; a PM2 "online" status alone is
not an acceptance check. Both failures have hermetic regression tests.

The longer idle check also found a SQLite connection leak: transaction context
exit committed/rolled back but did not close connections. The worker eventually
exhausted file handles. Each transaction now explicitly closes its connection,
including on rollback. A deterministic ownership test and the live descriptor
soak above verify the fix. A further CPU job and archive download pass after
the soak.

## Rollback

On telemetry, stop only `lhr-jobs` in PM2 and close the operator SSH tunnel.
On HIL, pause/cancel jobs first when they should stop, then stop/disable only
`lhr-runner`. Worker shutdown alone leaves Docker jobs running. Do not stop
`viewer_tool`, reset Tailscale Serve or modify the existing Compose projects.
